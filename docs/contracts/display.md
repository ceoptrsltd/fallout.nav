# Контракт: экран `/display` (агенты B, C; превью — D)

## Холст и геометрия

- Логический холст **768×576 px** (4:3, квадратные пиксели). Всё рисуется в этих координатах.
- **Зона безопасности:** `settings.display.safe_area_pct` (по умолчанию 5%) с каждой стороны →
  при 5%: `x 38.4 … 729.6`, `y 28.8 … 547.2`. Всё важное (компас, скорость, индикаторы) — внутри неё.
- Физический размер видимой области: `settings.display.screen` = **92 × 69 мм** → 1 мм ≈ 8.35 px холста.
  Минимально читаемое на кинескопе: текст ≥ 3 мм высоты (≈ 25 px), линии ≥ 2 px.
- Параметры URL:
  - `?pal=1` — режим устройства: окно Chromium 720×576, корневой элемент 768×576 масштабируется `transform: scaleX(0.9375)` от левого верхнего угла (кинескоп растянет обратно до 4:3).
  - `?preview=1` — внутри модального окна веб-интерфейса: без PAL-сжатия, фон прозрачный за пределами холста.
  - без параметров — как `preview`, но на весь экран браузера с центровкой (для отладки).

## Слои (снизу вверх) — владелец B, кроме HUD-компонентов

1. `<canvas id="map">` — карта (рендер B).
2. `<img id="camera">` — `src="/api/camera/mjpeg"`, `object-fit: cover` на весь холст; показывается при `telemetry.display.mode === "camera"`. Плавный переход 300 мс. При ошибке загрузки — повторная попытка каждые 2 с, надпись "NO CAMERA".
3. `<canvas id="wind">` — ветер вокруг машины (`drawWind` C): свой холст, чтобы анимация струек не перерисовывала HUD.
4. `<canvas id="hud">` — HUD. Цикл кадров (requestAnimationFrame) — у B; рисование элементов — функции C.

### Перерисовка по изменению (`web/display/map/retained.js`)

- HUD и ветер рисуются не прямо на холст, а в `RecordingContext` (тот же API Canvas 2D: записывает вызовы, сам ведёт
  состояние, `measureText` — у настоящего контекста, `ctx.canvas` — настоящий холст). Запись проигрывается на холст,
  только если отличается от прошлой (те же вызовы с теми же аргументами — на холсте уже ровно это), и в любом случае
  раз в 2 с и после загрузки шрифтов. Пиксели те же, что при прямом рисовании.
- Поэтому компоненты C: рисуют только через переданный `ctx`, не читают из него пиксели (`getImageData`), а спрайты
  после создания не меняют — `theme.js sprite()` помечает их холст `fnavStatic = true`, такие картинки сравниваются по
  ссылке; `drawImage` любого другого источника (и `Path2D`) делает кадр «всегда рисовать».
- Ветер на своём холсте: очищается только прямоугольник, который вернул `drawWind` (и прошлый).
- `?debug=1` — счётчики «drawn / skip» для HUD и ветра (статистика — на своём холсте); `?debug=1&verify=1` — те же кадры
  ещё и напрямую на скрытых холстах, раз в 30 кадров пиксели сравниваются (`verify N bad 0 max 0`).

### Экран «на охране» (`settings.display.armed_standby`, по умолчанию да)

- Пока `telemetry.alarm.state === "armed"` (не `arming`, не `triggered`, не `off`) — вместо карты и HUD чёрный экран:
  тусклое `ALARM ON` с замком и часы (`ui/standby.js drawStandby`, раз в минуту блок сдвигается на несколько px —
  не выжигать кинескоп). Вместо requestAnimationFrame — таймер раз в секунду; холст перерисовывается, только когда
  сменилась минута. Карта и тайлы не планируются, ветра нет, поток MJPEG закрывается сразу (без задержки 30 с),
  геймпад не опрашивается.
- Любое другое состояние (по телеметрии, 10 Гц) — сразу обычный экран; `triggered` — с крупной плашкой охраны.
- Задний вид, вызванный кнопкой камеры на охране (`telemetry.display.camera === "rear"`), будит экран — показать, что за
  фургоном; кнопка ещё раз (`camera` снова `front`) — снова «на охране».

### Задний вид (камера заднего вида, docs/contracts/camera.md «Задняя камера»)

- Клавиша камеры (`camera_switch`) / короткое нажатие кнопки GPS-модуля → fnav-core: `display.camera = "rear"`,
  `display.mode = "camera"`, `reason = "rear"`, `display.rear_mirror`; `telemetry.camera_rear` — статус задней
  (`null` — выключена). Логика — `map/rearview.js`, слой видео — `map/camera.js`, метка — `ui/rear.js`.
- Слой видео берёт `api/camera/rear/mjpeg` (удалённо — `?fps=5`), кадр целиком, вписанный в видимую область
  кинескопа (`display.safe_area_pct`: поля, которые он срезает, — с краёв кадра ничего не пропадает; `object-fit:
  contain`: IP-камеры 16:9 — поля сверху и снизу вместо обрезки), зеркально (только видео, HUD — нет) при
  `rear_mirror`; вместе с
  `display.mirror_x` (зеркалит весь экран для RV-50) складывается правильно. Последний кадр прежней камеры не
  показывается до первого кадра новой.
- HUD: светлая плашка `REAR` вверху (между часами и компасом; с компасом v2 — справа от часов, под лентой).
  Нет картинки — по центру `REAR CAMERA / NO SIGNAL` вместо стоп-кадра; первые 1,5 с подключения — чёрный экран,
  дольше — `CONNECTING`. «Нет сигнала»: статус null / disabled / stopped / error без кадров, `recording` без кадров
  дольше 1,5 с, ошибка `<img>`. Статус снова «есть видео» — поток переподключается (оборванный MJPEG ни `load`, ни
  `error` не шлёт).
- В `state.view`: `camera: "front" | "rear"`, `rearSignal: "ok" | "wait" | "connecting" | "no_signal" | null`.
- Стоп-кадры для обзора — `ui/alarm-level-preview.html`: `rear`, `rear-169`, `rear-v2`, `rear-nosignal`, `rear-connecting`.

## Данные

- B подключается к `ws(s)://<host>/ws`, переподключение с backoff 0.5→5 с, при обрыве > 3 с — индикатор "NO LINK".
- Настройки — из сообщения `{"type":"settings"}` (и `GET /api/settings` при старте).
- Между пакетами телеметрии (10 Гц) B интерполирует позицию и курс для плавности 30–60 fps.
- Геймпад (меню игр, `ui/games-menu.js`): `navigator.getGamepads()` — только пока `telemetry.display.gamepad`
  (fnav-core видит `/dev/input/js*` или `/dev/input/by-id/*-event-joystick`). Раз позвав его, Chromium опрашивает
  устройства ~250 раз в секунду (≈5 % ядра CM4) даже без геймпада; геймпад пропал — опрос останавливается
  (снятие последнего слушателя `gamepadconnected`). Нет поля (старое ядро) — опрос как раньше.

## Объект `state`, который B передаёт в компоненты C (каждый кадр)

```js
state = {
  now: 1729440000.12,            // performance-время в секундах (для анимаций)
  telemetry: { ...Telemetry },    // последнее сообщение как есть (fnav/models.py)
  // telemetry.speed_limit: {kmh, src: "osm"|"zone"|"default"} | null — знак у спидометра (fnav/core/speedlimit.py)
  weather: { ...WeatherStatus } | null, // {"type":"weather"} от fnav-core (fnav/core/weather.py, Open-Meteo + кэш)
  settings:  { ...Settings },     // текущие настройки
  view: {
    mode: "map" | "camera",
    orientation: "heading_up" | "north_up",
    bearingDeg: 247.3,           // текущий (анимированный) поворот карты: на сколько градусов карта повёрнута; 0 в north_up
    headingDeg: 247.3 | null,     // анимированный курс (истинный) для цифр компаса, null если неизвестен
    vehicleHeadingDeg: 247.3 | null, // курс иконки машины (быстрое сглаживание)
    compassHeadingDeg: 247.3 | null, // курс для КОМПАСА: минимальное сглаживание (display.compass_smoothing_s ≈ 0.1 с), без задержек
    headingSource: "gps"|"mag"|"blend"|"none",
    speedMps: 12.3 | null,
    zoom: 17.42,                  // текущий анимированный зум
    hasFix: true,
    connected: true,              // есть ли связь с fnav-core
    internet: true | null,
    recording: true,
    wallMs: 1729440000123,        // Date.now() — для часов (ui/clock.js); время машины = UTC + telemetry.system.utc_offset_min
    vehicleX: 384, vehicleY: 386, // машина на экране (ветер вокруг неё, ui/weather.js)
  },
  canvas: { w: 768, h: 576, safe: { x: 38.4, y: 28.8, w: 691.2, h: 518.4 }, pxPerMm: 8.35 },

```

## API компонентов C (`web/display/ui/`)

Все — ES-модули, без зависимостей, рисуют в переданный `CanvasRenderingContext2D`, ничего не хранят глобально, кроме кэша спрайтов.

```js
// web/display/ui/index.js — единая точка входа для B
export async function loadUi();                       // загрузить шрифты/спрайты (await перед первым кадром)
export function drawHud(ctx, state, { wind = true } = {}); // ВСЁ поверх карты/видео: компас, скорость, индикаторы, «НЕТ GPS» и т.п.
                                                      // wind: false — без ветра (B рисует его на своём холсте)
export function drawWind(ctx, state);                 // струйки ветра вокруг машины → {x, y, w, h} (за них не выходят) | null
export function drawStandby(ctx, state);              // экран «на охране»: чёрный фон, ALARM ON, часы (state.view.wallMs)
export function drawVehicle(ctx, x, y, rotationDeg, state); // иконка машины в точке (x,y) холста; rotationDeg — поворот на экране (0 = вверх)
export function drawTrail(ctx, points, state);         // след: points = [{x,y,age_s}] в координатах холста (опционально)
export const compassStyles = [{ id: "v1", name: "…" }, …];  // варианты дизайна; выбранный — settings.display.compass_style
```

- Ориентация берётся из `settings.display.orientation` (fallback — `telemetry.display.orientation`).
- B вычисляет экранную позицию и поворот машины: `heading_up` → машина в `(w/2, h*vehicle_anchor_y)`, `rotationDeg = vehicleHeadingDeg − bearingDeg` (иконка сначала поворачивается сама, затем карта догоняет — см. ниже); `north_up` → центр, `rotationDeg = vehicleHeadingDeg`.
- **Эффект поворота (heading_up):** `vehicleHeadingDeg` следует за курсом быстро (`display.vehicle_rotation_lag_s`, ~0.25 с), `bearingDeg` карты — медленно, с замедлением в конце (`display.map_rotation_lag_s`, ~1.5 с, критически демпфированная пружина без перелёта), изменения курса меньше `display.map_rotation_deadband_deg` карту не крутят. В итоге на повороте иконка отклоняется от вертикали, а затем карта плавно доворачивается и линия машины снова совпадает с осью экрана.
- **Компас вращается без задержек** по `view.compassHeadingDeg` (не по `bearingDeg` карты — пружина карты компас не тормозит): `heading_up` — шкала вращается так, что вверху текущий курс; `north_up` — шкала неподвижна (N вверху), вращается стрелка. Цифры курса — тоже по `compassHeadingDeg`.
- C делает страницу-галерею `web/display/ui/gallery.html`: все варианты компаса, иконка машины, спидометр, на холстах 768×576 с mock-состоянием, в **физическом размере** (калибровка — см. ниже), с анимацией курса и скорости.

## Физический размер на ноутбуке (общий для D и галереи C)

- Калибровка хранится в `localStorage["fnav.preview.pxPerMm"]` — сколько CSS-px в одном реальном миллиметре на этом экране (по умолчанию `96 / 25.4 ≈ 3.78`).
- Калибровка: пользователь подгоняет ползунком прямоугольник под банковскую карту (85.60 × 53.98 мм).
- Масштаб холста для 1:1: `scale = (screen.w_mm * pxPerMm) / 768`.
- Общий модуль: `web/display/ui/physical.js` (пишет C) — `getPxPerMm()`, `setPxPerMm(v)`, `renderCalibrator(container)`; D импортирует его из `/display/ui/physical.js`.

## Стиль

- Пост-апокалипсис, Fallout (Pip‑Boy) / Mad Max: потёртый металл, трафаретные шрифты, моноширинные цифры, заклёпки, «приборная» эстетика.
- Экран **монохромный** — дизайн обязан читаться в оттенках серого: контраст по яркости, тёмная подложка/обводка под всем поверх карты (карта пёстрая). Цвет допустим, но смысл не должен держаться на цвете.
- Fonts: open license only (OFL/Apache), Latin is enough (UI is English), лежат локально в `web/display/ui/fonts/` (+ файл `LICENSES.md`). Никаких запросов в интернет.
- Иконка машины — оригинальная векторная работа «в стиле» (не копировать чужие изображения).
